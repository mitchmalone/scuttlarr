<!-- v0.8.0 — first-launch setup; install gets the bar and the launcher -->

## Breaking changes

- none for upgraders. Two defaults flip in this release (the bar on, Desktop tiling
  off), but a `config.json` written by an earlier version is pinned to what it had on
  first launch: keys you never set keep their old values (bar off, tiling on), keys you
  did set are never touched, and the file is stamped `defaultsVersion: 2` so it happens
  once. Only fresh installs get the new defaults.

## Highlights

**Setup on first launch.** A fresh install used to open on an empty prompt, and every
rung was found by reading docs or digging through Settings. Now the first summon walks
through the hotkey, the bar, agent tracking, the theme and tiling, one question per
screen over a pixel field that answers your typing, ends on a recap of what will change,
and applies it with one Enter. The bar and agents screens show the real bar, not a
drawing. `setup ⏎` runs it again from your current config. Upgraders never see it.

**Install gets the bar and the launcher.** The code now matches what the README always
said: the bar is on out of the box and Desktop tiling is a rung you turn on. A fresh
install writes no `aerospace.toml` and no longer probes for AeroSpace.

**Off means off, and config writes never collide.** Turning the bar off now stops its
snapshot and polling rather than hiding it. Every config write goes through one atomic
writer that re-reads and patches the file, so two panels saving at once can't undo each
other, and a quicklink never overwrites a config it can't parse. Plugin panels keep
their place across the 5 s refresh.

**Update checks that recover.** Each source has its own interval (mas, pnpm and mise
every 5 minutes, brew and the scuttlarr self-check every 30), and a source that errors
retries in 5 minutes instead of sitting in the bar for six hours.

**Away mode gets a MacBook-sized desk.** The iPad screen it holds for Screens is now
1600x1200 HiDPI instead of the iPad's own 1366x1024: still crisp, no longer cramped.

**scuttlarr.com wears your theme.** A pixel hero that reacts to your typing, and one
picker that dresses the whole site in any of the 14 app themes, demo included. The copy
now describes the v0.8.0 defaults and first-launch setup.

## Performance receipts

Measured on a release build of main (`2f651bf`, `tauri build --bundles app`, unsigned),
2026-10-21, on a Mac mini (M4, 16 GB, one 5K display, macOS 26.6), launched directly so
the `[scuttlarr perf]` log is visible. Bar on; agents monitor, tiling and the machine rung
off; no plugin services running.

| Metric                         | Budget   | This release |
| ------------------------------ | -------- | ------------ |
| Hotkey → panel visible         | < 100 ms | 0.32 ms      |
| Cold start → hotkey registered | < 1 s    | 216 ms       |
| Idle memory (panel hidden)     | < 120 MB | 114 MB       |

Hotkey → panel is the native side of the summon path, median of 11 summons from the tray
(0.19–3.9 ms). Cold start is the median of 7 launches (165–248 ms). Idle memory is
`scripts/mem.sh`, steady across three readings a minute after launch.

**Idle memory is not comparable to v0.7.0's 169 MB.** That was the primary Mac with the
agents monitor and two Bun plugin services running; this machine runs neither, so the
reading is the app alone on a light config. The shrink is still its own task.
